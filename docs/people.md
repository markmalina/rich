# Люди

Расширение протокола **0.3.2**. Версия листа **1.0**. Лист **Люди**, таблица **PeopleDirectory**.
Машинная спецификация: [schemas/people.json](../schemas/people.json).

Карточка хранит известные сведения о человеке и его связь с владельцем карточки. Это частный справочник, а не публичная база контактов.

| Колонка | Название | Ключ | Смысл |
| --- | --- | --- | --- |
| A | Имя для отображения | `display_name` | Короткое или привычное имя из источника; отдельно от имени по документам. |
| B | Связь | `relationship` | Связь с владельцем карточки: свободный текст; несколько связей допустимы. |
| C | Телефон | `phone` | Текст: сохранять +, ведущие нули и исходный формат. Не угадывать номер. |
| D | Фамилия | `last_name` | Только известная фамилия. |
| E | Имя | `first_name` | Отдельная часть ФИО; не подменять прозвищем. |
| F | Отчество | `patronymic` | Только известное отчество. |
| G | Обращение | `address_form` | Как обращаться к человеку, в переданной формулировке. |
| H | Ссылка на Телеграм | `telegram_url` | Только предоставленная или подтверждённая ссылка. Не строить адрес по догадке. |
| I | Владелец | `owner` | Владелец карточки и контекст связи; это не владение человеком. |
| J | ID человека | `person_id` | Стабильный ID человека для ссылок между листами; не номер строки. |

«Владелец» означает владельца карточки/контекста учёта, а не собственность на человека. Друг, родственник, жена и другие связи — свободный текст: варианты не ограничены списком. Разные владельцы могут описывать связь с одним человеком по-разному.

## Приём и обработка

- Обычные Work направляют любые контактные сведения во «Входящие»; назначенный обработчик распределяет их в справочник. В явном поручении владельца разрешённый исполнитель может создать структуру или карточку в указанном объёме.
- Не заполнять справочник людьми из памяти только потому, что появилась вкладка. Создание пустой структуры не означает импорт контактов.
- Фамилия, имя, отчество, отображаемое имя и обращение независимы. Не делить неоднозначное имя по догадке; сохранить исходное представление во входящих и уточнить.
- Телефон хранить текстом, включая знак плюс и ведущие нули. Telegram-ссылка хранится текстом как передана/подтверждена. Не угадывать адреса, номера и принадлежность аккаунта по имени.
- Карточка пригодна при известных отображаемом имени, владельце контекста и стабильном ID человека. Остальные поля могут оставаться пустыми.
- До создания нового человека проверить существующие карточки в разрешённом диапазоне. Совпавшие имена или общий телефон сами по себе не доказывают одну личность; объединять только при подтверждённом тождестве.
- ID человека сохраняется при изменении имени и перемещении строки. Несколько контекстов владельцев могут ссылаться на тот же подтверждённый ID. Номер строки не является ID.
- Происхождение карточки хранится во «Входящих»: результат обработки связывает целевую карточку по ID человека и владельцу с исходными ID. Изменение сведений принимает новое связанное уточнение и сохраняет историю источников.
- Расширять диапазон нативной таблицы при добавлении строк, сохранять типы, форматы и буквальные значения. Прочитать записанные поля обратно. Наличие контакта не даёт права писать этому человеку или предоставлять его данные другим.

## Чтение и связь с личными записями

Для записи о человеке читать отображаемое имя и нужные поля в пределах доступа; не публиковать всю карточку. В личных листах текст «Кому» сохраняется вместе с ID человека, когда личность установлена. Если человека ещё нет в справочнике или он не установлен, оставить ID пустым и сохранить переданный текст.
