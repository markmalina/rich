Репозиторий `markmalina/rich` публичный; основная ветка — `main`. README описывает протокол 0.3.1: инструкции, схемы таблиц и промпты для работы личного ассистента с частной Google Таблицей. Исполняемая серверная система пока не заявлена как готовая. Корневой файл `LICENSE` по этому пути при проверке не найден (ответ API 404). Это не доказывает отсутствия любых лицензионных уведомлений в других файлах. Открытых issues поиск не вернул.

## Цель обсуждения, а не утверждённые условия

Публичные материалы должны быть доступны для бесплатного использования. Желаемая модель — общая развивающаяся структура, доступность улучшений для других участников и возможность включать их в основной проект. Обсуждаются уведомления о доработках, согласование изменений и недопустимость скрытых ответвлений. Пока это идеи для выбора модели, а не принятая лицензия.

## Рекомендация

1. Программную реализацию, исполняемые компоненты и связанные программные исходники выпускать под GNU AGPL версии 3; предложенный фиксированный идентификатор — `AGPL-3.0-only`.
2. Самостоятельные тексты протокола, документацию, неисполняемые промпты и авторские описания структуры/шаблоны рассмотреть под `CC-BY-SA-4.0`. Для машинных схем и промптов, встроенных в программу, определить границу отдельно и явно пометить файлы: одна и та же часть не должна оказаться под случайно несовместимыми условиями.
3. Правила участия в официальном проекте оформить отдельно: предложение изменений, описание причины, обсуждение совместимости, pull request, рассмотрение и принятие. Предлагать возвращать улучшения в общий проект; не выдавать это пожелание за обязанность по AGPL.
4. Частные пользовательские данные не включать в лицензию публичных материалов. Название, логотип и статус официальной версии обозначить отдельной политикой бренда.

Это набор лицензий для разных объектов, а не выбор пользователем любой из двух лицензий на один и тот же файл.

## AGPL: действие и границы

AGPL — copyleft: лицензия сохраняет свободу использования и изменения покрываемого произведения. При передаче производной программы применяются требования к лицензии и исходникам; при изменении программы с сетевым взаимодействием §13 требует бесплатно предлагать соответствующие исходники всем удалённым пользователям этой версии. Получив исходники, проект может использовать улучшения при соблюдении лицензии.

AGPL не требует отправлять изменения первоначальному автору, открывать каждую личную экспериментальную ветку или получать разрешение на форк. Она разрешает частную работу без распространения; сетевое использование изменённой программы проверяется отдельно по §13. Предоставление исходников пользователям не тождественно публикации репозитория для всех. Коммерческое использование и платные услуги разрешены. Добавлять произвольный запрет форков или обязательное предварительное согласование как условие AGPL нельзя: §§7 и 10 ограничивают дополнительные ограничения.

Примеры: изменённый сервер для клиентов должен предлагать своим удалённым пользователям исходники; личный локальный эксперимент без передачи копий и сетевых пользователей не создаёт всеобщей обязанности публикации; самостоятельный форк может развиваться отдельно при соблюдении условий.

## Почему текущему протоколу нужна отдельная оценка

Пользование текстовыми инструкциями через стороннего ИИ не равнозначно запуску изменённой AGPL-программы с сетевыми пользователями. Нельзя обещать, что одно добавление AGPL к Markdown автоматически заставит раскрыть каждый изменённый промпт.

CC BY-SA 4.0 позволяет использовать и перерабатывать материалы, включая коммерческое использование. При распространении переработок нужны указание авторства, отметка изменений и ShareAlike. Частные изменения публиковать не требуется; обязательной передачи редактируемого исходника и специальной серверной обязанности эта лицензия не вводит. Creative Commons рекомендует специальные программные лицензии для ПО.

Если обязательны раскрытие любых изменений, личное уведомление автору и его разрешение на каждое ответвление, стандартные предложенные лицензии этого не дают. Потребуется отдельно разработанная модель договора/лицензии; запрет самостоятельных производных версий несовместим с обычным определением open source. Просто назвать такой текст AGPL с дополнениями было бы неверно.

## Структура, данные и права

Авторское право защищает охраняемую форму произведения, а не саму идею, процедуру или метод работы. Поэтому охват простых названий колонок, функциональных связей и коротких машинных схем зависит от их охраноспособности и применимого права. Лицензия не создаёт исключительного права на любую похожую систему.

ODbL 1.0 отдельно регулирует права на базы данных и требует доступности производной базы либо изменений при соответствующем публичном использовании. Она может быть полезна для будущих общих справочников, но не выбрана как лицензия каждой личной базы System Rich: её требования к содержимому производных баз нужно оценивать отдельно. Ни ODbL, ни AGPL не заменяют правила владения и доступа к личным сведениям.

## Следующий шаг для принятия решения

Согласовать модель: независимые ответвления разрешены, а раскрытие и повторное использование улучшений регулируются copyleft; официальный протокол развивается через основной репозиторий. Затем проверить право лицензировать публикуемые материалы и лицензии зависимостей, составить карту файлов, добавить тексты лицензий, уведомления и CONTRIBUTING. До этого не заявлять, что проект уже выпущен под выбранной лицензией.
