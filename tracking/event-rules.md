# Правила учёта событий в Tracker

Эти правила описывают общую схему записи в «БАЗУ». Вкладка «Правило» в конкретной таблице содержит ссылку на эту схему. Владелец может указать там личные правила, которые имеют приоритет для его таблицы.

## Поля строки

| Поле | Что хранить |
| --- | --- |
| Дата и время | Дата и время события по Москве. Если время неизвестно, используйте время получения сообщения и отметьте ID события во «Входящих». Если неизвестно и время получения, оставьте время события пустым. |
| Событие | Нормализованное описание строки учёта. Исходное сообщение хранится во «Входящих». |
| Действие | Значение из справочника «Действия». |
| Количество, единица | Подписанный объём движения ресурса. Плюс означает поступление или зафиксированный результат, минус означает расход. Валюту указывайте кодом, например RUB или BYN. |
| Длительность | Минуты на действие или подход. Используйте известную длительность, иначе для упражнения и каждой строки покупки или оплаты берите одну минуту. |
| MET для события | Оценка интенсивности для конкретного занятия, если она известна. Пустое поле оставляет значение из справочника. |
| ID входящего | Ссылка на строку «Входящих», из которой получено событие. Источник, исходная фраза и сведения о времени находятся там. |
| Вес для расчёта | Масса тела в кг для расчёта энергии упражнения, если она известна. Массу еды и результат отдельного взвешивания вносят в количество и единицу события. |
| Описание для Face | Явно разрешённый текст для витрин. |
| ID события | Постоянный идентификатор события внутри этой «БАЗЫ». Все строки одного события имеют одинаковый ID. |
| Ресурс | Что учитывается. Например, вода, деньги, дистанция, повторения или калории. |
| Склад / счёт | Куда поступил ресурс или откуда он выбыл. Это может быть место хранения, банковская карта или тело. |
| Контрагент | Получатель или источник, если он известен и важен для события. |
| Собранное событие | Автоматическое описание из структурированных полей всех строк с тем же ID. Исходное описание доступно по ID входящего. |

## Связанные записи

- **Покупка.** Одно событие с двумя строками. «Приобретение» фиксирует ресурс со знаком плюс и место поступления. «Оплата» фиксирует списание со знаком минус, валюту и счёт. Обе строки имеют один ID события и один ID входящего. Для чека в первой строке указываются общая покупка и итог к оплате; сумма в числовых полях движения денег записывается только в строке «Оплата». Позиции чека остаются в распознанном тексте «Входящих».
- **Доход, расход и благодарность.** Фактическое внешнее поступление даёт положительную строку «Доход». Фактическое списание в пользу другого человека или организации даёт отрицательную строку «Расход». Укажите известные счёт и контрагента. Полученный неденежный подарок даёт положительную запись о подаренном ресурсе. Если владелец прямо сказал, что получил благодарность за перевод, добавьте отдельную строку «Благодарность» с тем же ID события, в условных единицах и без денежной оценки.
- **Перевод между своими счетами.** В одной валюте запишите две строки действия «Перевод между своими счетами» с равными по модулю суммами и противоположными знаками. Укажите разные счета, единый ID события и тот же ID входящего. Явно указанную комиссию храните отдельным внешним расходом. Если известен только факт исходящего перевода, сохраните действие «Перевод денег» до подтверждения принадлежности счёта получателя.
- **Групповой счётчик.** RX считает подтверждённые строки «Доход», «Расход» и «Оплата» с ресурсом «Деньги» по уникальным ID событий. Группа получает только число. Переводы между своими счетами, неопределённые «Переводы денег» и служебные строки исключаются. Прежние переводы остаются под своими названиями до уточнения владельцем.
- **Упражнение.** Строка действия фиксирует подход, результат и длительность. Строка «Расход калорий» с тем же ID фиксирует отрицательный расход в ккал со счёта «Тело» и не дублирует длительность. Для каждого подхода заводится своё событие. В Face расход показывается положительной величиной рядом с упражнением.
- **Оценка калорий.** Активный расход сверх покоя рассчитывается как `(MET − 1) × 3,5 × вес в кг / 200 × минуты`, округляется до 0,1 ккал и записывается со знаком минус. MET берётся из строки или справочника. Если расчёт невозможен, количество оставляется пустым. Длительность в одну минуту при отсутствии замера является допущением, а не хронометражем.

Одно входящее может дать несколько событий. ID события объединяет строки одного события, ID входящего ведёт к первоисточнику. Форматы входа, права и запуск описаны в [Telegram-пилоте](telegram-pilot.md).
