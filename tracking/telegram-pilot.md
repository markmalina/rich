# eRex · личный Telegram-пилот

eRex (RX) — личный помощник по лайф-трекингу. Его зарегистрированный адрес — [@ErexoBot](https://t.me/ErexoBot). Текущий пилот обслуживает одну настроенную «БАЗУ» и принимает личные сообщения от одного заданного Telegram ID. Он дополняет [работу с собственным ИИ](assistant-prompt.md).

## Что умеет

- Принимать текст, голосовые, фото и картинки JPG, PNG или WEBP до 18 МБ. Исходник и результаты распознавания связываются через «Входящие». Оригиналы хранятся на постоянном диске бота и доступны владельцу командой `/original ИМЯ_ФАЙЛА`.
- Применять [промпт](telegram-prompt.md), справочник и личные правила, при необходимости задавать один уточняющий вопрос. Нормализованные строки события связаны с входящим. Покупка и оплата записываются отдельно, позиции чека пока хранятся в его распознанном тексте.
- Читать «События» по дате, действию, категории и поисковой строке. Face обновляется по настроенному расписанию Google.

Голос отправляется в OpenAI Audio Transcriptions, по умолчанию используется `gpt-transcribe`. Текст и изображения обрабатывает Responses API с `gpt-5.4-mini` по умолчанию. Используйте доступ провайдера, выданный для вашего развёртывания.

[Обозначения проекта](../docs/glossary.md).

## Подключение

1. Создайте «БАЗУ» по [инструкции](../docs/google-base.md) или сверьте совместимость существующей. Подключите её через сервисный аккаунт с включённым Sheets API и правами редактора либо через Apps Script по инструкции ниже. Ссылки на таблицы и ключи вводятся в частной конфигурации.
2. Создайте отдельного бота через BotFather. Укажите токен и числовой ID владельца, добавьте настройки OpenAI и Google.
3. Соберите контейнер из корня репозитория (`docker build -t rich-tracker .`). Запустите один экземпляр с постоянным томом, например в `/data`. При запуске бот сверяет заголовки таблицы и проверяет Telegram.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TRACKER_OWNER_ID` | Telegram ID владельца |
| `OPENAI_API_KEY` | Ключ отдельного OpenAI-проекта RX |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | JSON учётных данных при подключении сервисным аккаунтом |
| `TRACKER_APPS_SCRIPT_URL` | URL развёртывания Apps Script с окончанием `/exec` |
| `TRACKER_APPS_SCRIPT_TOKEN` | Случайный секрет развёртывания из 64 шестнадцатеричных символов |
| `TRACKER_SPREADSHEET_ID` | ID «БАЗЫ» |
| `TRACKER_DATA_DIR` | Путь к постоянному диску оригиналов, SQLite и позиции чтения Telegram |
| `TRACKER_MODEL`, `TRACKER_TRANSCRIBE_MODEL` | Необязательная замена моделей |

Отправьте текст о приёме пищи, голосовое об упражнении, вымышленный чек и запрос на чтение. Сверьте «Входящие», события и настроенную витрину. Проверьте повторную обработку и доступ с другого аккаунта. Локальные тесты запускаются командой `python -m unittest discover -v`.

## Подключение через Apps Script

1. В аккаунте, у которого есть доступ к выбранной «БАЗЕ», создайте проект Apps Script. Добавьте [скрипт](sheets-bridge.gs) и расширенный сервис **Google Sheets API** с именем `Sheets`.
2. В свойствах проекта задайте `RX_SPREADSHEET_ID` и `RX_BRIDGE_TOKEN`. Укажите конкретную таблицу и случайный 256-битный секрет в нижнем регистре hex. Храните секрет в свойствах скрипта и конфигурации Railway. URL запроса содержит только адрес развёртывания.
3. Разверните как веб-приложение с выполнением от имени установившего его аккаунта. Для вызова из Railway нужен режим «Все», в котором Google принимает запрос без входа. Код проверяет секрет, ID таблицы и разрешённый диапазон для каждой операции. Для первой проверки используйте отдельную таблицу с синтетическими записями.
4. Задайте `TRACKER_APPS_SCRIPT_URL` и `TRACKER_APPS_SCRIPT_TOKEN` вместе. При наличии любой из них бот ожидает обе и выбирает скрипт. Проверьте совпадение `TRACKER_SPREADSHEET_ID` в Railway и `RX_SPREADSHEET_ID` в скрипте.

[Развёртывание веб-приложения](https://developers.google.com/apps-script/guides/web) · [Расширенный сервис Google Sheets](https://developers.google.com/apps-script/advanced/sheets)

Многопользовательский бот с созданием отдельных файлов через Google OAuth описан в [плане](roadmap.md). Если собственный ИИ уже подключён к Google от имени пользователя, для создания «БАЗЫ» по инструкции достаточно этого подключения.
