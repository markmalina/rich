# eRex · личный Telegram-пилот

eRex (RX) — личный помощник по лайф-трекингу. Его зарегистрированный адрес — [@ErexoBot](https://t.me/ErexoBot). Текущий пилот обслуживает одну настроенную «БАЗУ» и принимает личные сообщения от одного заданного Telegram ID. Он дополняет [работу с собственным ИИ](assistant-prompt.md).

## Что умеет

- Принимать текст, голосовые, фото и картинки JPG, PNG или WEBP до 18 МБ. Исходник и результаты распознавания связываются через «Входящие». Оригиналы хранятся на постоянном диске бота и доступны владельцу командой `/original ИМЯ_ФАЙЛА`.
- Применять [промпт](telegram-prompt.md), справочник и личные правила, при необходимости задавать один уточняющий вопрос. Нормализованные строки события связаны с входящим. Покупка и оплата записываются отдельно, позиции чека пока хранятся в его распознанном тексте.
- Читать «События» по дате, действию, категории и поисковой строке. Face обновляется по настроенному расписанию Google.

Голос отправляется в OpenAI Audio Transcriptions, по умолчанию используется `gpt-transcribe`. Текст и изображения обрабатывает Responses API с `gpt-5.4-mini` по умолчанию. Используйте доступ провайдера, выданный для вашего развёртывания.

[Обозначения проекта](../docs/glossary.md).

## Подключение

1. Создайте «БАЗУ» по [инструкции](../docs/google-base.md) или сверьте совместимость существующей. Подключите её через сервисный аккаунт с включённым Sheets API и правами редактора либо через Apps Script по инструкции ниже. Ссылки на таблицы и ключи вводятся в частной конфигурации.
2. Подключите существующего бота владельца или создайте бота через BotFather при первой установке. Укажите токен и числовой ID владельца, добавьте настройки OpenAI и Google.
3. Соберите контейнер из корня репозитория (`docker build -t rich-tracker .`). Запустите один экземпляр с постоянным томом, например в `/data`. При запуске бот сверяет заголовки таблицы и проверяет Telegram.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TRACKER_OWNER_ID` | Telegram ID владельца |
| `TRACKER_TELEGRAM_ONLY` | Значение `1` запускает ответы в личном чате до подключения «БАЗЫ» |
| `OPENAI_API_KEY` | Ключ отдельного OpenAI-проекта RX |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | JSON учётных данных при подключении сервисным аккаунтом |
| `TRACKER_APPS_SCRIPT_URL` | URL развёртывания Apps Script с окончанием `/exec` |
| `TRACKER_APPS_SCRIPT_TOKEN` | Случайный секрет развёртывания из 64 шестнадцатеричных символов |
| `TRACKER_SPREADSHEET_ID` | ID «БАЗЫ» |
| `TRACKER_DATA_DIR` | Путь к постоянному диску оригиналов, SQLite и позиции чтения Telegram |
| `TRACKER_MODEL`, `TRACKER_TRANSCRIBE_MODEL` | Необязательная замена моделей |

При `TRACKER_TELEGRAM_ONLY=1` для запуска достаточно токена Telegram, ID владельца и диска. Команда `/start` показывает статус подключения. На остальные сообщения бот сообщает, что их нужно прислать повторно после подключения «БАЗЫ». Для обычного режима уберите эту переменную после настройки Google и OpenAI.

В личном чате владельца `/status` проверяет доступ к заголовкам подключённой «БАЗЫ». Команда не создаёт запись, не обращается к модели и не возвращает ссылки, чаты или содержимое дневника.

Отправьте текст о приёме пищи, голосовое об упражнении, вымышленный чек и запрос на чтение. Сверьте «Входящие», события и настроенную витрину. Проверьте повторную обработку и доступ с другого аккаунта. Локальные тесты запускаются командой `python -m unittest discover -v`.

RX сохраняет подготовленную запись на постоянном диске до отправки и читает «События» после неё. Ответ об успешной записи приходит после сверки всех ожидаемых строк и их связи с исходником. Потерянный ответ Google переводит запись на повторную сверку. RX запоминает отправку при перезапуске и проверяет тот же файл, избегая второй отправки пакета с неясным результатом. Пример для проверки — перевод между своими счетами, у которого нужны и списание, и поступление. Если сохраняется расхождение, оператор сверяет пакет с исходником в той же «БАЗЕ». Работа со следующими сообщениями может продолжаться.

Перед записью во «Входящие» RX сохраняет ID исходника и назначение в SQLite. При неопределённом ответе он повторно читает ту же БАЗУ и ждёт появления строки. Явный отказ на прямой записи Google Sheets, например 429, разрешает повторную попытку. Для моста Apps Script ошибка может относиться к получению ответа после записи. Новые записи того же профиля ждут в порядке получения, остальные чаты продолжают работать. Временная очередь хранит только поля, нужные для повторной обработки личного сообщения. После обработки запись удаляется из очереди. При восстановлении сохраните постоянный том и проверьте командой `/pilot_health` число ожидающих и их возраст.

## Подключение через Apps Script

1. В аккаунте, у которого есть доступ к выбранной «БАЗЕ», создайте проект Apps Script. Добавьте [скрипт](sheets-bridge.gs) и расширенный сервис **Google Sheets API** с именем `Sheets`.
2. В свойствах проекта задайте `RX_SPREADSHEET_ID` и `RX_BRIDGE_TOKEN`. Укажите конкретную таблицу и случайный 256-битный секрет в нижнем регистре hex. Храните секрет в свойствах скрипта и конфигурации Railway. URL запроса содержит только адрес развёртывания.
3. Разверните как веб-приложение с выполнением от имени установившего его аккаунта. Для вызова из Railway нужен режим «Все», в котором Google принимает запрос без входа. Код проверяет секрет, ID таблицы и разрешённый диапазон для каждой операции. Для первой проверки используйте отдельную таблицу с синтетическими записями.
4. Задайте `TRACKER_APPS_SCRIPT_URL` и `TRACKER_APPS_SCRIPT_TOKEN` вместе. При наличии любой из них бот ожидает обе и выбирает скрипт. Проверьте совпадение `TRACKER_SPREADSHEET_ID` в Railway и `RX_SPREADSHEET_ID` в скрипте.

[Развёртывание веб-приложения](https://developers.google.com/apps-script/guides/web) · [Расширенный сервис Google Sheets](https://developers.google.com/apps-script/advanced/sheets)

## Тестовый режим подключения через RichDriveBox

В режиме `TRACKER_PILOT=1` первое личное сообщение запускает подготовку раздельных частных файлов «БАЗА» и Face. RX сохраняет связь с Telegram ID на постоянном диске. Личное сообщение об учёте обрабатывается после создания комплекта. Участник работает через Telegram, а групповой отчёт подключается отдельно.

1. Настройте Drive API, Sheets API и Google OAuth с разрешением `drive.file` и фоновым обновлением токена под аккаунтом RichDriveBox. В секретах тестовой среды задайте `TRACKER_OAUTH_CLIENT_ID`, `TRACKER_OAUTH_CLIENT_SECRET` и `TRACKER_OAUTH_REFRESH_TOKEN`. Используйте отдельного Telegram-бота и отдельный постоянный том.
2. В поддерживающем секреты терминале выполните `python -m bot.onboarding --create-registry` с теми же OAuth-настройками. Команда выведет ID частного реестра. При прерванной настройке используйте `--resume-registry ID` для того же файла. Укажите ID в `TRACKER_PILOT_REGISTRY_ID` и установите [общий скрипт Face](face.md#общий-скрипт-для-пилота-rx). Реестр создаётся один раз для всего пилота.
3. Задайте `TRACKER_PILOT=1`, токен отдельного Telegram-бота, ключ модели и путь к постоянному диску. Фактическое имя тестового бота укажите в `TRACKER_PILOT_BOT_USERNAME`, адрес RichDriveBox — в `TRACKER_PILOT_GOOGLE_EMAIL`. Для отдельного тестового бота оставьте `TRACKER_OWNER_ID` пустым. Если ID владельца задан, его личный путь требует обычных настроек существующей «БАЗЫ» и сохраняется отдельно. `TRACKER_TELEGRAM_ONLY` и пилотный режим взаимоисключающие.
4. С двух Telegram-аккаунтов отправьте разные вымышленные записи. Проверьте, что получились два разных комплекта, каждый без общедоступных разрешений. Перезапустите процесс с тем же диском и убедитесь, что файлы повторно не создаются. У одного участника начните уточнение, у второго сделайте запрос по своему журналу. Повторите записи через API при выключенном RX и проверьте обе витрины.

При неопределённом результате создания файла RX ищет файл по служебной метке. Новое создание удерживается до подтверждения результата. Если поиск продолжает возвращать пустой список, оператор сверяет запрос с Google Drive перед восстановлением. Диск содержит привязки, состояние незавершённого создания и исходные вложения. Выпуск для новых пользователей требует успешной проверки живого Telegram и Google окружения.

Перед добавлением пары в реестр Face RX сохраняет отметку на постоянном диске. Если ответ Google потерян, повторное обращение читает реестр и открывает пару после появления её единственной строки. Пока результат неизвестен, добавление приостановлено для этого профиля. Однозначный отказ API, например 429, разрешает повтор после восстановления. Если строка так и не появилась, оператор сверяет результат запроса к Google и состояние пары до любых ручных изменений.

Перед живым прогоном можно запустить `python -m unittest bot.test_pilot_acceptance -v`. Тест проходит путь двух вымышленных пользователей и существующего владельца через рабочий цикл RX. Он проверяет раздельные файлы, повторы после перезапуска, состав группового отчёта и историю после выхода. Сетевые ответы Telegram и Google в этом прогоне имитируются. Общий скрипт Face проверяется отдельно командой `node --test tracking/test_face_sync.cjs`.

На тестовой службе команда `python -m bot.pilot_check --forbid-bot ErexoBot` проверяет, что токен относится к отдельному боту, а разрешение Google выдано нужным аккаунтом. Проверяет закрытый реестр, наличие inline для настроенных групп, роль бота в них и доступ к указанным групповым Face. Команда читает метаданные и заголовки. Результат не содержит токенов и личных записей. Ключ модели проверяется на наличие. Общий таймер и запись тестовых участников проверяются живым прогоном отдельно.

[OAuth для фонового доступа](https://developers.google.com/identity/protocols/oauth2/web-server) · [Разрешения Google Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

### Стенд закрытого личного входа

У выделенного личного воркера `TRACKER_PRIVATE_ADMISSION_IDS` задаёт JSON-список разрешённых Telegram ID, `TRACKER_PRIVATE_TERMS` — текст условий, который участник видит до подключения. Оба параметра задаются вместе. Пустой список оставляет вход только настроенному оператору-владельцу. При некорректном списке или отсутствии текста воркер завершает запуск. Без обоих параметров действует прежний режим.

Участник читает `/pilot_terms` и принимает показанную версию командой `/pilot_consent`. При изменении текста требуется новое подтверждение. `/pilot_withdraw` приостанавливает обработку. После отзыва или удаления ID ожидающие данные остаются закрытыми для повторной обработки до восстановления допуска и подтверждения актуальной версии. Это действие не удаляет историю автоматически. Пока профиль есть в списке приглашённых, `/pilot_privacy` доступна и при приостановленной обработке или ожидающей очереди. Допуск проверяется перед личными командами, кнопками, повторной сверкой очереди и напоминаниями обеих сторон.

Первый ввод участника после подтверждения сохраняется в локальной очереди до вызова Google. При временной ошибке воркер продолжит с того же исходника. Первичное подключение возобновляется только для явно отмеченного входящего. Для уже подготовленной пары пропавшая локальная привязка остаётся на сверке. Стендовый прогон: `python -m unittest bot.test_pilot_acceptance -v`.

Тот же допуск применяется к сопровождению и закрытым групповым отчётам. После отзыва второй участник не получает новые данные по связи, учебный день у него нельзя подтвердить, а клиент сохраняет просмотр собственных данных и возможность завершить связь. Групповой предпросмотр связан с принятой версией условий. При отзыве или смене версии старый предпросмотр не принимается, а отправленное через него сообщение удаляется администратором-ботом. Уже подтверждённая история сохраняется по действующим правилам группы.

## Личное сопровождение

Личное сопровождение доступно командой `/coach` при `TRACKER_COACHING=1`. Владелец может назначить роль трекера через `/coach_allow ID`. Трекер выдаёт одноразовое приглашение `/coach_invite`, клиент выбирает практику и отдельно передаёт трекеру условия и отметки. Напоминания включаются клиентом. После отзыва трекер теряет доступ к просмотру отметок. Оплата идёт напрямую трекеру, eRex фиксирует только ручное подтверждение. Для проверок сам владелец может использовать `/coach_invite demo`. Учебная связь отмечается отдельно от рабочей. Данные сопровождения хранятся на диске RX и не передаются в «БАЗУ», ИИ или группу.

## Вечерний отчёт в тестовой группе

Групповой режим можно подключить к действующему личному RX, не включая автоматическое создание «БАЗ». Готовая подключённая «БАЗА» требуется для автора отчёта; отдельно проверяется согласованное членство для выдачи истории. Настройки Telegram inline, скрытой истории и прав бота действуют для обоих режимов. OAuth группового Face требуется при подключении отдельной таблицы витрины. При ошибке проверки группы RX оставляет доступной работу в личном чате.

Используйте отдельного бота с подключённым режимом `TRACKER_PILOT=1`. Включите inline у BotFather. Добавьте его администратором закрытой тестовой супергруппы со скрытой историей. После запуска бот получает события вступления и выхода. Для проверки участники вступают после включения режима. Бот запоминает фактическое время вступления и дополнительно проверяет членство перед чтением БАЗЫ.

Задайте в приватных настройках `TRACKER_REPORT_GROUPS`. В примере одна группа, один трекер и один участник. Идентификаторы и название вымышлены.

```json
[
  {
    "chat": -1000000042,
    "name": "Группа «Практика»",
    "tracker": 100001,
    "members": {
      "100001": {
        "practices": [{"action": "Приседание", "label": "Приседания", "unit": "повт."}],
        "finance": true
      },
      "100002": {
        "practices": [{"action": "Приседание", "label": "Приседания", "unit": "повт.", "minimum": 10}],
        "finance": true
      }
    }
  }
]
```

Согласуйте список практик, единицы и минимум с участником. При отсутствии поля `minimum` требуется факт отчёта. Трекер и участник могут выбрать разные минимумы одной практики. Настройку применяйте к следующему отчёту. RX записывает подтверждённые внешние поступления и расходы отдельно от своих переводов. Для счётчика берутся `Оплата`, `Расход` и `Доход` с ресурсом «Деньги» и валютой. Переводы между своими счетами и неопределённые «Переводы денег» исключаются. В текст уходит только число уникальных операций.

В группе отправьте `/report@имя_тестового_бота`, нажмите одну из кнопок и проверьте предпросмотр. Бот засчитывает исходное сообщение через inline только при совпадении группы, отправителя и выбранного отчёта. Предпросмотр, пересылка и повтор доставки зачёта не дают. Вчерашнюю публикацию можно отправить с опозданием. Исправление хранится отдельной версией. Для проверки просрочки используется время отправки Telegram и полночь по Москве.

В личном чате с RX команда `/reports` показывает три последних отчёта из каждой доступной группы. Номер страницы указывается через пробел, например `/reports 2`. Подтверждённые исправления видны отдельными публикациями. RX проверяет текущее членство и выдаёт только публикации после вступления. При выходе участник теряет доступ через RX, а его отчёты остаются в группе. Поле `name` в профиле участника задаёт согласованное имя для истории и Face.

### Закрытый групповой Face

Подтверждения и все версии хранятся на постоянном диске RX. Face трекера содержит последнюю опубликованную версию на человека и отчётный день. Файл остаётся у трекера и используется только им. Участники читают разрешённую историю через личный чат с RX.

1. Получите разрешение `drive.file` для того же приложения Google OAuth от Google-аккаунта трекера. В терминале подставьте его токен обновления в `TRACKER_OAUTH_REFRESH_TOKEN` и запустите `python -m bot.group_face --group -1000000042 --create` с ID тестовой группы. Сохраните выведенный ID. Если настройка прервалась после создания файла, запустите команду с `--resume ID`. Храните токены в настройках сервиса.
2. Добавьте ID файла в поле `face` нужной группы в `TRACKER_REPORT_GROUPS`. В `TRACKER_REPORT_FACE_TOKENS` задайте JSON-объект с токеном обновления трекера по каждому ID группы с Face. Используйте тот же OAuth client ID и client secret, что для пилота. Оставьте созданному файлу общий доступ «Ограниченный», без дополнительных читателей и редакторов.
3. Отправьте исходный отчёт и его исправление. Убедитесь, что в Face одна строка с исправлением для этого участника и дня. Прервите доступ к файлу на время одной публикации и восстановите его. RX повторит выгрузку. Затем проверьте личную историю у нового участника и после его выхода из группы.

RX пишет в Face отдельным подключением Google OAuth трекера. Перед записью он проверяет владельца, доступ и привязку файла к группе, затем сверяет записанные значения. Для группы без настроенного Face публикация и личная история работают через базу RX.

## Учебный поток и подтверждение пакета

Включение — `TRACKER_SCHOOL=1`. Команда ученика `/school`. Для общего старта оператор сначала создаёт именованный поток командой `/pilot_cohort_create ID ГГГГ-ММ-ДД demo|live`, затем создаёт место `/pilot_offer ID_ученика demo|live ID_потока` и сверяет сумму через `/pilot_paid ID_заказа 9900 | номер_подтверждения`. Переданная в `/pilot_paid` дата не меняет общий старт именованного потока. Повторный заказ того же человека в этом потоке не увеличивает состав, а новый поток создаёт отдельное участие. `/pilot_cohort_member ID_потока ID_ученика withdrawn` фиксирует выход без изменения исходного знаменателя. Старый сценарий без ID потока остаётся совместимым и принимает персональную дату старта. Для рабочего заказа требуется настроенный продавец и открытый приём заказов; управляющий режим в Telegram не принимает деньги.

Одна подтверждённая покупка открывает место на 21 день, обязательство выдать 21 × 80 г и семь календарных дней личного сопровождения наставником начиная с даты старта. За эти семь дней отдельная кнопка оплаты сопровождения не показывается и такое подтверждение отклоняется. Дни 1–7 посвящены роли клиента, 8–14 сопровождению, 15–21 продвижению. Ученик может оставить личный черновик или отдельно передать работу наставнику. Для завершения нужны работы дней 7, 14 и 21 и подтверждение наставника; отдельный публичный пост не нужен. Учебные материалы сгенерированы как демонстрационная редакция, время проверяется по Москве. Завершение курса, подтверждённая практика, число фактически платящих клиентов и оплаченные дни считаются независимо; учебные подтверждения и включённые в пакет дни заработком не считаются.

### Учебная оплата из личного чата

`TRACKER_DEMO_CHECKOUT=1` при `TRACKER_SCHOOL=1` включает `/pay`. Необязательный `TRACKER_SCHOOL_COHORT` связывает новое учебное место из `/pay` с заранее созданным учебным потоком; несуществующий поток не создаёт заказ и возвращает понятную ошибку. В личном чате участник выбирает предложение, нажимает «Оплатить», читает условия учебного режима и нажимает «Я оплатил». eRex продолжает сценарий сразу. Денег, ссылки на платёжный сервис и фискального чека нет. Учебные подтверждения участвуют только в учебной сводке. Старые подтверждения сохраняются. Пока флаг включён, рабочие подтверждения оплаты и возврата закрыты.

| Предложение | Следующий шаг |
| --- | --- |
| Трекинг на 21 день, 4 200 ₽ | Появляется подарочный набор 21 × 80 г и открывается `/tracking`. В нём можно отмечать питание, активность и финансы по московским дням. Доступ к Google-дневнику настраивается отдельно. |
| Школа и продвижение, 9 900 ₽ | Открывается `/school_day ID` и учебная выдача набора. |
| Отдельный учебный заказ гранолы | Заказ появляется в `/pay` после `/pilot_goods ID demo …`. После подтверждения доступен `/pilot_delivery ID`. |
| День у трекера, 100 ₽ | После согласия по учебному сопровождению в `/pay` доступен текущий активный день. Подтверждение ведёт к `/coach_report ID`. |

Первый QR, передавший код банки до подтверждения оплаты, становится источником заказа трекинга. Он также добавляется к ожидающему заказу, который открыли через `/pay`. Следующий QR открывает тот же заказ и сохраняет источник. Для подтверждённого заказа источник закреплён. Кнопки принимаются только в личном чате владельца заказа, а учебный день у трекера подтверждает только клиент действующей учебной связи. `/pilot_export` включает собственные отметки `/tracking`.

## Сверка выдачи и эксплуатация

При `TRACKER_FULFILLMENT=1` оператор фиксирует резерв, отгрузку, выдачу и возврат. Повторите основание только при повторе той же операции. Исполнителю выдачи назначается конкретный заказ. Оплата товара, возврат денег и отзыв доступа к курсу записываются раздельно. Для публичного QR адрес заказа и наличие берутся только из конфигурации продавца.

При `TRACKER_OPERATIONS=1` RX создаёт ежедневный локальный комплект на постоянном диске: SQLite, копию журнала удалений и JSON-манифест с размером, SHA-256 и отпечатком схемы обоих файлов. `/pilot_health` показывает свободное место и количество неподтверждённых записей. `/pilot_backup` делает новый проверенный комплект того же дня. Для проверки восстановления скопируйте все три файла в отдельный контур и используйте новый путь командой `python -m bot.operations КОПИЯ НОВАЯ-БАЗА --deletion-ledger КОПИЯ-ЖУРНАЛА --manifest МАНИФЕСТ`. До создания восстановленной БАЗЫ команда сверяет оба файла с манифестом, затем применяет журнал удалений и проверяет SQLite. Для возврата в рабочую среду передайте также актуальную проверенную копию журнала через `--current-deletion-ledger АКТУАЛЬНЫЙ-ЖУРНАЛ`. Она добавляет удаления после снимка. При переносе на новый рабочий том поместите актуальный журнал также в `operations/erasures.sqlite` до первого запуска. Закрытый поток после восстановления требует заново подтвердить условия. Команды подтверждения из прежней среды для восстановленной копии недействительны. Очередь и учётные операции остаются доступны для сверки. Рабочую БАЗУ команда не заменяет.

`/pilot_health` также показывает время последнего успешного опроса Telegram и возраст самого старого ожидающего события. Для очереди, перенесённой со старого кода, время наблюдения начинается при миграции. `TRACKER_OPERATIONS_ALERTS=1` включает сообщение оператору для очереди старше 15 минут или нехватки места на диске. Один продолжающийся инцидент даёт одно уведомление. Текст уведомления состоит из фиксированных технических кодов. Внешний мониторинг остаётся отдельным каналом.

`/pilot_export` возвращает собственные учебные работы, свои отметки и заказы в личный чат. `/pilot_privacy school` открывает запрос на обработку учебных работ, `/pilot_privacy all` регистрирует общий запрос оператору. Учётные документы, дневники Google и оригиналы не входят в автоматическое удаление учебных работ. Сохранённая выдача в Telegram обрабатывается отдельно. Для защиты от потери тома нужна независимая от него копия; текущая команда создаёт копию на том же томе.

## Вложения и запись без ИИ

Ответьте `/original` на собственное сохранённое вложение или выберите имя в `/originals`. Форматы OGG, JPG, PNG и WebP поддерживаются до 18 МиБ включительно. `/original` выдаёт копию из личного контура запросившего участника.

В Telegram Web голос можно прислать как голосовое сообщение или приложить OGG-файл. Если браузер передал файл с расширением `.ogg`, `.oga` или `.opus` без распознанного типа, eRex проверяет заголовок Ogg с дорожкой Opus или Vorbis. В личной «БАЗЕ» расшифровка находится во «Входящих» рядом с именем оригинала. При отсутствии у отправителя подключённой «БАЗЫ» бот сообщает об этом до загрузки файла.

Для проверки Telegram Web в учебном режиме откройте личный чат eRex и отправьте `/voice_check`. Бот пришлёт синтезированную русскую фразу про 15 приседаний как голосовое сообщение. В меню этого сообщения нажмите «Переслать», выберите тот же чат eRex и сохраните подпись. В течение десяти минут бот может сверить возвращённое вложение. Успех входящего голоса подтверждает ответ «входящее голосовое Telegram», размер 7155 байт и SHA-256 `2bc4371e5359d2a4d447992ca19ca548c78795c6bf29abfc4cfbd366126b844f`. Если доступен только «Ответить», отправьте в ответ `/voice_verify`. Для этого пути бот отдельно указывает «файл голосового из ответа». После перезапуска процесса запросите свежий образец.

Обе проверки работают в текущем боте без микрофона, Google-таблицы и обращения к модели. При приёмке микрофона и распознавания в своём разрешённом дневнике отправьте вымышленную фразу обычной записью с микрофона. Сверьте распознанное количество, одну строку события, его исходник и возврат оригинала командой `/original`. Фиксируйте результат каждого шага отдельно.

`/record` показывает формат ручной записи. Например, `/record Завтрак | Гранола | 80 г` или `/record Приобретение | Покупка | 360 RUB | Карта`. Ручной ответ на собственный сохранённый оригинал добавляет событие к тому же исходнику. Последним полем можно передать дату и время МСК. Вместо ещё неизвестного количества используйте `?`. Внутренний перевод указывается действием «Перевод между своими счетами» и парой `Исходный счёт → Счёт получателя`.

`TRACKER_AI_DISABLED=1` оставляет ручную запись и сохранение вложений доступными без ключа модели. `TRACKER_AI_DAILY_CALLS` задаёт общий лимит обращений за календарный день МСК. Разбор и распознавание голоса считаются отдельными обращениями. Неудачное обращение также учитывается. Значение `0` закрывает новые обращения при сохранении ручной записи. При исчерпании лимита входящее и оригинал сохраняются. Счётчик обращений не является сверкой расходов в валюте.

## Возвращение учеников на контрольные дни

Оператор видит отчёт в `/pilot_cohorts demo` или `/pilot_cohorts live`. После режима можно передать дату отчёта. Для именованного потока D7 и D21 показываются как «не наступил», «предварительно» в сам контрольный день или «итог» после него. Основной знаменатель — уникальные участники, зачисленные не позднее общего старта; поздние участники выводятся отдельной выборкой, а вышедшие остаются в исходном знаменателе. Считаются открытие урока учеником или отправка работы именно в контрольный календарный день МСК. Повторные открытия, просмотры наставника и незачисленные заказы в числитель не добавляются. Совместимый отчёт старых персональных стартов остаётся отдельными строками. Удаление личных учебных данных убирает отметки активности из списка источников.

После временной ошибки ежедневная копия повторяется не чаще чем через пять минут. Дата успешной копии фиксируется после её создания.
