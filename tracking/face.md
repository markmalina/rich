# Витрины Face

«БАЗА» хранит журнал. Face — отдельная Google Таблица, куда копируются значения выбранных категорий. Например, упражнения, питание и замеры можно вывести в одну таблицу, а практики и режим дня — добавить во вторую. Разрешения на просмотр задаются для каждого файла отдельно в Google Диске.

## Установка для одной «БАЗЫ»

1. Создайте пустую частную Google Таблицу с названием выбранной витрины. Переиспользуйте начальную вкладку: она должна называться «События» и иметь заголовки из объекта `face` в [схеме](../schemas/google-base-v1.json). Генератор заполняет её и форматирует дату и время при установке через batchUpdate.

   ```bash
   python -m tracking.bootstrap --title 'Мой Face' --face --batch --default-sheet-id 123456789
   ```

2. На вкладке Faces в «БАЗЕ» добавьте точное название файла, ссылку на вкладку «События» с `#gid=…` и логические значения категорий. Для галочек используйте флажки Google Таблиц со стандартными значениями TRUE и FALSE.
3. В «БАЗЕ» откройте «Расширения → Apps Script» и добавьте [скрипт](face-sync.gs). В разделе «Сервисы» добавьте расширенный сервис Google Sheets API. Запустите `installFaceSync` от имени аккаунта, который может редактировать «БАЗУ» и все назначенные витрины. Скрипт связывается с текущей «БАЗОЙ» в свойствах скрипта. Повторная установка от того же аккаунта использует уже имеющиеся триггеры.
4. Добавьте контрольное событие, сверив выгрузку `Экспорт Faces` и отдельную витрину. Затем переключите одну категорию и проверьте состав витрины. Получателям выдавайте доступ к назначенному файлу Face.

## Запись и синхронизация

Триггеры обрабатывают ручные правки, изменение структуры и каждые пять минут сверяют данные после записи по API. Скрипт читает маршруты из Faces, проверяет заголовки и назначение, фильтрует разрешённые категории, записывает значения и читает их обратно. При совпадении повторная запись пропускается. Отчёт об ошибке перечисляет витрины, обновление которых не подтверждено.

Если у клиента отдельно доступен авторизованный вызов `syncFace`, вызывайте его один раз после подтверждения записи пакета в «БАЗУ». При частичном сбое повторите синхронизацию уже записанных строк. В поставляемом варианте клиентские записи через API подхватывает таймер Google. Прямой удалённый вызов требует отдельной точки запуска.

## Общий скрипт для пилота RX

Владелец файлов создаёт один самостоятельный проект Apps Script на своём Google-аккаунте, добавляет этот же файл и расширенный сервис Google Sheets API. Один периодический триггер следит за всеми парами. Для этого режима в том же аккаунте хранится закрытая таблица-реестр. Доступ к ней есть у оператора RX и аккаунта, под которым запускается скрипт. На листе «Пары» в первой строке должны быть заголовки `БАЗА`, `Face`, `Лист Face`. Дальше каждая строка содержит ID частной «БАЗЫ», ID её частного Face и числовой ID листа «События» этой витрины. Назначение в самой «БАЗЕ» должно совпадать с парой в реестре.

В свойствах самостоятельного проекта задайте `RICH_FACE_REGISTRY_ID` с ID закрытой таблицы. Один раз запустите `installRegisteredFaceSync`. При пустом реестре достаточно строки заголовков. Когда в реестре появятся пары, проверка запустится по тому же расписанию. Настройки в БАЗЕ позволяют выбрать категории, а адрес назначения берётся только из реестра. Каждая «БАЗА» и каждый Face участвуют в одной паре.

Для приёмки добавьте раздельные вымышленные события в две «БАЗЫ» через Google Sheets API при выключенном RX. Через общий скрипт каждая запись должна появиться только в своей витрине. Затем измените назначение на чужую витрину в одной тестовой «БАЗЕ». Скрипт не должен писать туда из этой базы, а проверка второй пары должна завершиться. Журнал указывает строку реестра без названий файлов и записей. При неверном реестре с повтором файла весь проход останавливается до записи.
