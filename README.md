# System Rich — личная база данных

**[System Rich — сайт](https://system.rich/)**. Личная база для финансов, питания, активности, практик, потребностей и возможностей под управлением личного ИИ-ассистента. Начните с собственной Google Таблицы и подключённого помощника. Полная ERP, PostgreSQL и сертификаты взаимного доверия — будущие релизы, а не возможности текущего протокола.

[Описание сайта и публичные тексты](docs/site/README.md). Репозиторий содержит открытые инструкции; частные данные остаются у их владельцев. Прежнее написание Reach сохранено в некоторых документах протокола.

Версия протокола: **0.3.1**. Версия входной схемы: **0.3**. Репозиторий: `rich`.

Google-таблица — база данных. Этот публичный репозиторий — описание её структуры и поведения: правила приёма, обработки и чтения, схемы и промпты. В нём нет содержимого базы.

## Модель

**Источник → «Входящие» → обработка Reach → предметные листы → чтение другими Work.**

«Входящие» принимают текст, файлы и связанные части произвольного сообщения. Строка не обязана соответствовать одной операции. В одной строке допустим целый отчёт или список; одно поступление допустимо разместить в нескольких связанных строках. Темы не ограничены: упражнения, покупки, передачи, производство и другие сведения.

Прочие Work добавляют исходные данные во «Входящие» и читают разрешённые листы. Назначенный обработчик Reach распределяет результаты и ведёт состояние обработки. Изменения структуры выполняются отдельной миграцией с сохранением записей.

## Статус версии

Версия 0.3 сохраняет универсальный входной формат и добавляет автора, предоставившего информацию, владельцев ресурсов и лист личных принципов. Авторство, предоставление, управление системой и владение не подменяют друг друга. Сведения о чужих ресурсах допустимы; личные принципы применяются только к их владельцу. Поля конкретного чека не являются обязательными колонками.

Документация не запускает автоматическую обработку. Предметная схема, детальные алгоритмы маршрутизации, триггеры, техническое разграничение прав, блокировки и надёжное восстановление после сбоев ещё требуют реализации.

## Изменение 0.1 → 0.2

- Единица строки — часть поступления, не хозяйственная операция.
- Произвольный исходный текст и вложения стоят отдельно от служебных полей.
- Добавлены пакет, порядок и количество частей, связь с предыдущей записью.
- Предметные поля перенесены в универсальные дополнительные сведения; при миграции сохраняется исходное представление версии 0.1.
- Формат записи и формат окончательных предметных операций разделены.

## Изменение 0.2 → 0.3

- Справа добавлены «Автор», «Предоставил», «Владелец»; общий префикс A:P и прежние строки сохраняются.
- Для владельцев нескольких ресурсов в одном источнике предусмотрено явное соответствие ресурса, владельца и основания.
- «Принципы» содержат текст личного правила и его владельца. Правила не становятся обязательными для всех участников.
- Недостающие личным правилам детали не блокируют приём сырого источника и не заполняются догадками.


## Уточнение протокола 0.3.1

При видимом расхождении входящих данных с личным принципом система сообщает человеку через Work приёма: конкретное расхождение, владелец, номер и текст принципа, запрос исправления. Исходник сохраняется; уточнение поступает новой связанной записью. Принципы проверяются при приёме, обработке и после уточнения. Форматы листов остаются 0.3; миграция данных не требуется. Фоновая проверка и межчатовый транспорт этим изменением не запускаются.
