# Участие в System Rich

Спасибо за предложения и улучшения. Официальный протокол развивается в этом репозитории.

## Как предложить изменение

1. Опишите в issue проблему, предлагаемое поведение и пользу для участников. Для небольшой ясной правки можно сразу открыть pull request.
2. Укажите затронутые файлы, версии протокола и схем, совместимость и нужную миграцию.
3. Приложите изменения отдельной веткой или pull request. Для структуры обновляйте согласованно текстовое описание и машинные схемы; сохраняйте данные и происхождение записей.
4. Покажите проверку, соответствующую изменению. Для документации достаточно проверить ссылки и согласованность; для будущего исполняемого компонента — проверить изменённое поведение.
5. Поддерживающий проект рассматривает предложение и принимает, запрашивает правки либо отклоняет его с объяснением. Отправка предложения не означает принятия.

Открытость проекта не обязывает принимать любое улучшение. Пока изменение не принято и не опубликовано как версия официального протокола, оно остаётся предложением или отдельной версией автора.

## Лицензия вклада и авторство

Отправляя вклад для включения, вы предлагаете его под лицензией соответствующего материала из [карты лицензирования](docs/licensing/README.md): AGPL-3.0-only для программной части и машинных интерфейсных схем; CC-BY-SA-4.0 для самостоятельных текстов и материалов протокола.

Вы подтверждаете, что вправе предоставить такой вклад под указанными условиями. Укажите авторов и происхождение заимствований, сохраните их уведомления. Если есть отдельные условия или сомнение в совместимости, сообщите об этом до включения. Сторонние компоненты не перелицензируются автоматически.

Автор сохраняет свои права. Исключительные права не передаются проекту; отдельный CLA или передача авторства не требуются этим порядком. Участники могут использовать принятый вклад при соблюдении применимой лицензии.

## Форки и возврат улучшений

Самостоятельные ответвления разрешены условиями лицензий. Мы приглашаем сообщать о полезных улучшениях и предлагать их в основной проект. Это порядок сотрудничества, а не дополнительное лицензионное требование обязательной передачи всех изменений именно нам.

Соблюдайте обязанности вашей лицензии: для изменённой сетевой AGPL-программы — предложение соответствующих исходников её удалённым пользователям; для распространяемых адаптаций текстов — авторство, отметка изменений и ShareAlike. Личные экспериментальные изменения не объявляются обязательными к всеобщей публикации.

Совместимость с официальной структурой проверяется по заявленной версии и фактическим форматам. Отдельный форк не становится официальной версией автоматически. Подробнее: [политика названия](BRAND_POLICY.md).

## Приватность

Не помещайте частные базы, реальные чеки и записи, личные принципы, ID таблиц, частные ссылки, ключи и другие секреты в файлы, issues, pull requests и их обсуждения. Используйте синтетические примеры без персональных данных.

Если для воспроизведения нужна частная информация, сначала согласуйте разрешённый частный канал с владельцем. Issue не даёт разрешения на доступ к чужим данным.
